答辩可说的 ER 关系要点

  • user 1:N goods — 一个用户可以发布多个商品 (user_id 外键)
  • goods 1:N favorite — 一个商品可以被多人收藏 (goods_id)
  • goods 1:N deal_records — 一笔交易生成两条记录 (买家一条 type=0，卖家一条 type=1)
  • status 字段控制商品状态 — 0=在售(显示"确认购买")、1=已售(灰色不可点击)

五、数据流全景

完整的读写数据链路

📖 读数据（查询商品列表为例）

步骤代码位置操作
1. 获取实例MainActivity.loadGoods()DBHelper.getInstance(this) — 单例获取数据库帮助类
2. 获取可读库同上.getReadableDatabase() — 返回 SQLiteDatabase 对象
3. 执行查询同上db.rawQuery("select * from goods where title like ? order by id desc", new String[]{"%手机%"})
4. 游标遍历同上while (cursor.moveToNext()) { ... } — 逐行读取
5. 封装对象同上goodsList.add(new Goods(id, title, price, ...)) — Cursor → Goods 实体
6. 关闭游标同上cursor.close() — 必须关闭，否则内存泄漏
7. 刷新界面同上adapter.notifyDataSetChanged() — 通知 RecyclerView 重新渲染

✏️ 写数据（购买商品为例）

步骤代码位置操作
1. 更新状态DetailActivity.confirmPurchase()ContentValues → db.update("goods", ...) — status 改为 1
2. 买家记录同上ContentValues → db.insert("deal_records", ...) — type=0
3. 卖家记录同上ContentValues → db.insert("deal_records", ...) — type=1
4. 刷新界面同上按钮变灰色显示"已售出"
💡 为什么一笔交易要插入两条记录？
买家角度看是"买入"（type=0），卖家角度看是"卖出"（type=1）。两条记录分别关联不同 user_id，这样买家和卖家在各自的"买卖记录"页面都能看到这笔交易。

八、核心技术底层原理

SQLite 嵌入式数据库

SQLite 不是服务器，是一个文件级数据库引擎。整个数据库就是一个 .db 文件。Android 将其编译进系统，App 通过 JDBC 风格的 API 直接读写本地文件，零配置、零网络依赖。

单例模式 (DBHelper)

synchronized getInstance() 确保全局只有一个数据库连接。如果每次操作都 new，会产生多个 SQLiteDatabase 对象同时写同一个文件，导致"database is locked"错误。

Cursor 游标

Cursor 是查询结果的"指针"，不一次性加载所有数据。调用 moveToNext() 指针下移一行，按需读取该行各列。这样即使 goods 表有10万条记录也不会 OOM。

RecyclerView 视图复用

屏幕可见约7个 item，但 RecyclerView 只创建约10个 ViewHolder。滑出屏幕的 ViewHolder 被回收，新滑入的直接复用，只更新数据不重新 inflate。这就是为什么 10000 条数据也能 60fps 流畅滑动。

ContentValues 防注入

本质是 HashMap<String,Object>。Android 内部自动转义特殊字符（如单引号），不会像拼接 SQL 字符串那样产生 SQL 注入漏洞。

SharedPreferences

轻量级 XML 键值对存储。getSharedPreferences("user", MODE_PRIVATE) 生成 /data/data/包名/shared_prefs/user.xml 文件。适合存少量配置（用户名、登录态），不适合大数据。

Intent 传参

页面间通过 putExtra("key", value) 打包数据，底层是 Bundle（基于 Parcelable 序列化）。不同于 Java Serializable，Parcelable 是 Android 优化的内存序列化，性能更高。

Glide 图片加载

自动处理 解码→缩放→缓存 三条链路。根据目标 ImageView 的实际尺寸自动下采样（不会把4000×3000的原图直接加载进内存），加载过的图缓存在内存和磁盘。

九、答辩老师可能问的问题

#问题参考答案
1 数据存在哪里？服务器在哪？ 纯本地 App，没有服务器。所有数据存在手机 SQLite 数据库文件 /data/data/com.example.campusmarket/databases/market.db 中。断网也能正常使用。
2 数据库有几张表？什么关系？ 4张表：user、goods、favorite、deal_records。user 1:N goods，goods 1:N favorite 和 deal_records。通过 user_id 和 goods_id 外键关联。
3 一笔购买交易怎么记录的？ confirmPurchase() 做了三件事：① 更新 goods.status=1 ② 给买家插入 type=0 记录 ③ 给卖家插入 type=1 记录。这样双方都能在买卖记录里看到。
4 首页怎么实现模糊搜索？ loadGoods(kw) 执行 SQL: select * from goods where title like '%关键词%' order by id desc。EditText 绑定 TextWatcher，用户每输入一个字就触发一次查询。
5 怎么判断"编辑"还是"购买"按钮？ DetailActivity 里比较 curId == goodsUserId：登录用户ID == 商品发布者ID → 显示编辑按钮；否则显示购买按钮。已售商品(status=1) 显示灰色"已售出"。
6 图片存在哪里？ 用户选图后，通过 copyImage() 将系统相册的图片以流的方式复制到 App 内部目录 /data/data/包名/files/images/，数据库中只存文件路径（String），不存图片二进制。
7 登录状态怎么保持的？ LoginActivity 登录成功后将 username 和 user_id 写入 SharedPreferences。下次打开 App 自动读取。退出登录时 clear() 清空。
8 RecyclerView 为什么能高效滚动？ 视图复用机制：只创建屏幕可见数量+2个缓冲的 ViewHolder。滑出屏幕的被回收，滑入的直接复用，不重复 inflate 布局。内存占用恒定，不随数据量增长。
9 DBHelper 为什么用单例？ 如果每个 Activity 各自 new DBHelper，会产生多个 SQLiteDatabase 连接同时操作同一个文件，可能导致"database is locked"错误。单例保证全局只有一条连接。
10 后台通知怎么实现的？ CheckService 是一个 Android Service，启动后台线程每30分钟查一次 goods 表 count。数量增加时通过 NotificationManager 发送系统通知，Service 设置 START_STICKY 被杀后自动重启。
